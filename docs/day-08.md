# Day 8: save a classification

Allow 20–30 minutes. Today you will start PostgreSQL, save one sample result,
and read it back. Docker and Docker Compose are available in this workspace.
This exercise makes no model API calls.

## 1. Start the database

Create `compose.yaml` beside `README.md`:

```yaml
services:
  db:
    image: postgres:17
    environment:
      POSTGRES_USER: ticket_app
      POSTGRES_PASSWORD: local_learning_only
      POSTGRES_DB: tickets
    ports:
      - "127.0.0.1:15432:5432"
    volumes:
      - ticket_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ticket_app -d tickets"]
      interval: 2s
      timeout: 5s
      retries: 15

volumes:
  ticket_data:
```

This uses the [official PostgreSQL image](https://hub.docker.com/_/postgres).
The password is for this local exercise. The port is bound to your own machine;
`15432` helps avoid clashing with an existing PostgreSQL installation.
The named volume stores the database files between container starts.

From the project root, run:

```bash
docker compose up -d --wait db
docker compose ps
```

The first run downloads the image. Wait until `db` is healthy. If startup fails,
run `docker compose logs db` and share the error.

## 2. Save one result

Open the database's SQL terminal:

```bash
docker compose exec db psql -U ticket_app -d tickets
```

At the `tickets=#` prompt, run:

```sql
CREATE TABLE IF NOT EXISTS classifications (
    id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    message text NOT NULL,
    result jsonb NOT NULL,
    created_at timestamptz NOT NULL DEFAULT now()
);

INSERT INTO classifications (message, result)
VALUES (
    'My payment went through twice.',
    '{"category":"billing","priority":"high","sentiment":"neutral","summary":"Customer reports a duplicate payment."}'
)
RETURNING id;

SELECT id, message, result->>'category' AS category, created_at
FROM classifications
ORDER BY id;
```

The sample result is entered manually. Later, the API will insert its actual
classification. Running the INSERT again adds another row.

`id` is generated by the database. `created_at` records when the row was created.
`jsonb` stores the classification as JSON; `->>` reads a field as text. PostgreSQL
checks that the JSON is valid, but this table does not enforce our category or
priority rules. See the [PostgreSQL JSON documentation](https://www.postgresql.org/docs/17/datatype-json.html).

## 3. Check that the row survives a restart

Type `\q` to leave the SQL terminal. In your shell, run:

```bash
docker compose stop db
docker compose up -d --wait db
docker compose exec db psql -U ticket_app -d tickets -c "SELECT id, message FROM classifications ORDER BY id;"
```

Your saved row should still be there. Use `docker compose stop db` when you want
to stop the database. Keep the named volume: `docker compose down -v` would delete
its stored data.

You're done when you have saved a row and read it back after restarting. Send:

```text
Database healthy: yes/no
Saved row ID: __
Category read back: __
Row still present after restart: yes/no
```
